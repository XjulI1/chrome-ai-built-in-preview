🎙️ Voice Chat —

Boucle conversationnelle in-browser via 3 étapes : SpeechRecognition (voix → texte) → LanguageModel (Gemini Nano, texte → réponse) → SpeechSynthesis (texte → voix).

⚙️ Local vs Internet — détail par étape

1. SpeechRecognition — STT  réseau probable

  • Sur Chrome / Edge : webkitSpeechRecognition envoie typiquement l'audio aux serveurs Google pour transcription.
  • Firefox : non supporté. Safari : services Apple (réseau).
  • Pour du 100 % offline → utiliser la card Whisper (ONNX, WebGPU/WASM) dans transformers.html.

2. LanguageModel (Gemini Nano) — LLM  100% local

  • Modèle embarqué dans Chrome, téléchargé une seule fois via chrome://components.
  • Aucune requête sortante au moment du session.prompt(). System prompt, temperature et historique restent dans le renderer.

3. SpeechSynthesis — TTS  variable selon la voix

  • Voix système (ex. macOS « Thomas », « Amelie ») : 100 % offline.
  • Voix « réseau » (ex. Google français, Microsoft Online) : streaming depuis Google/Microsoft.
  • getVoices() n'expose pas toujours le flag localService ; pour garantir l'offline, choisir explicitement une voix système.

Micro & permissions : getUserMedia est purement local (autorisation OS/navigateur), aucune donnée ne sort par ce biais. Les seuls passages réseau viennent des implémentations browser des Web Speech APIs.
